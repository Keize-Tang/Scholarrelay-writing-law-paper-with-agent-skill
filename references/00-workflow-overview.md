# 00 · 流程总览

> **这套流程的切分依据**：机构订阅文献库（知网等）的访问控制是三层叠加的
> ——**① IP 授权**（须连入学校 webvpn）+ **② 登录态** + **③ 下载额度**。
> 任何一层不过，拿到的只是摘要页而不是全文。**这是授权问题，不是技术问题。**
>
> 所以流程**切在授权边界上**：只用一次，人做需要授权的那几步（检索/导出/下载，几十秒），
> 其余全部交给 AI。详见 `01-division-of-labor.md` 与 `02-cnki-export-guide.md` 第零节。

## 一图看懂

```
阶段0 立项定锚        人:给方向/期刊/截稿/字数   → AI:写《写作启动包》
   ↓
阶段1 题录获取        人:登录webvpn→知网检索+导出题录txt+下载PDF   ← 需机构授权，AI 不代劳
   ↓
阶段2 解析分级        AI:parse_cnki.py → 题录.tsv → 《文献筛选清单》A/B/C
   ↓
阶段3 精读笔记        AI:pdf2txt.py 批量转文本 → 逐篇精读 → 《文献精读笔记》
   ↓
阶段4 分章写作        AI:先报引用清单 → 人确认 → 写正文 (v1→v2→...)
                     收尾做标点规范化(normalize_cn.py)+标题编号校正
   ↓
阶段5 修订与体检      AI:整篇重写新版本 + redundancy.py 版本塌方预警  ★决定成败
   ↓
阶段6 编号校验        AI:cnki2gbt.py 生成条目 → renumber.py 重排 → validate.py 校验
   ↓
阶段7 投稿排版        AI:md2docx.py → 期刊体例 Word
   ↓
阶段8 模拟审稿        ★ 换独立窗口 + 换更强模型
                      AI(mk_review_packet.py 清洗稿件 → 送审) → 落盘《审稿意见_M_N.md》
   ↓
阶段9 选刊与投递      人:选刊决策 + 填作者信息、上传投稿系统
```

## 阶段之间的咬合点

流程之所以能跑通，靠的是**五个交接文件**。它们同时是"压缩包"和"合同"：

| 交接文件 | 上游 | 下游 | 咬合作用 |
|---|---|---|---|
| `写作启动包` | 阶段0 人的决策 | 阶段4 AI 写作 | 把选题/期刊/字数/法条/数据/文献锚点一次锁定，避免写作中反复回头问 |
| `文献筛选清单` | 阶段2 AI 分级 | 阶段1 人下载 | 明确告诉人"只要下这 25 篇"，避免下无用文献 |
| `文献精读笔记` | 阶段3 AI 精读 | 阶段4 AI 引用 | 引用时能定位到"哪篇、哪页、哪句话" |
| `审稿稿_M<N>.md` + `审稿任务说明_M<N>.md` | 阶段8 写作窗口 | 阶段8 **审稿窗口** | **跨窗口的唯一通道**：隔离的代价是必须靠文件交接 |
| `审稿意见_M<N>.md` | 阶段8 审稿窗口 | 阶段5 修订 | 让"改了什么、还有哪些没改"可追溯 |

> **注意阶段 8 的特殊性**：它是全流程中**唯一跨窗口**的一环。
> 写作侧与审稿侧互不可见，所以两端都必须落盘。
> 详见 `08-self-review.md` 第二节。

## 二、为什么"阶段 5 修订"要单列成阶段

这是三次真实合作对照出来的结论：**决定论文成败的不是资料准备，是修订方式。**

| | 思想史论文（最好） | 规范分析论文（**被放弃**） |
|---|---|---|
| 资料准备 | 三轮文献需求 | 启动包/分级清单/精读笔记**全齐** |
| 迭代方式 | 整篇重写（每版一个完整文件） | 字符串替换打补丁 |
| 修订脚本 | 0 个 | **7 个 `fix_*.py`** |
| 版本字数曲线 | 6.1k→7.3k→7.6k→8.8k→8.6k | 9.9k→12.7k→13.7k→**5.8k** ⚠️ |
| 最后的修订脚本名 | — | `fix_v6_chegulun.py`（"车轱辘话清除：11 处修订"） |
| 结局 | 定稿 | 拦腰砍断后放弃 |

资料准备最完备的那个项目失败了，因为它用打补丁的方式修订。
**车轱辘话不是写出来的，是补丁生产出来的。**

详见 `09-revision-discipline.md`。

## 三、三条容易被忽视的规矩

**规矩一：上下文压缩是常态，靠文件不靠记忆。**
长对话一定会被压缩。所以每次重大决策后，**立刻写进 `写作启动包`**，而不是留在对话里。启动包顶部要写清"本文件 + X + Y 三份文件即可恢复全部关键知识"。

**规矩二：版本只增不改。**
正文用 `_v1 _v2 _v3`。看起来冗余，但出问题时能立刻回滚，也能看出"第 2 版到第 3 版改了什么"。覆盖式修改是最常见的事故源。

**规矩三：任何增删文献 → 必跑 renumber + validate。**
这不是可选项。编号错位是"低级但致命"，审稿人一眼可见，且改起来最费时间。机器一秒的事情不要用人眼赌。

## 四、时间分配经验值（以 1.2 万字、A档 25 篇为例）

| 阶段 | 占比 | 说明 |
|---|---|---|
| 阶段1 人操作 | 20% | 检索、导出、下载，不可压缩 |
| 阶段2+3 解析精读 | 25% | 最容易被低估，但决定写作质量上限 |
| 阶段4 写作 | 25% | 分章进行，每章报引用清单 |
| **阶段5 修订** | **15%** | **至少两轮，且每轮整篇重写** |
| 阶段6+7 校验排版 | 5% | 脚本自动化，很快 |
| 阶段8 自审 | 10% | 换视角找硬伤 |

**最常见的失败模式**：
1. 跳过阶段 2+3 直接写 → 引用是虚的，后面整段重写；
2. 跳过阶段 5 的重写纪律，用补丁迭代 → 越改越冗余，最后被迫腰斩。
