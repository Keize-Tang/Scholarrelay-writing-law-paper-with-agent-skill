# 16 · 隐私保护与脱敏规范

> **本工作流的素材来自真实论文，而技能包是要公开发布的。** 这两件事天然冲突。
> 本章规定：**哪些信息不能进入公开仓库、怎么处理、发布前怎么检查。**

---

## 一、三类不能公开的信息

### 1. 身份信息

| 类别 | 具体项 |
|---|---|
| 姓名 | 真实姓名、笔名、学号 |
| 单位 | 学校、学院、系、导师姓名 |
| 联系方式 | 手机、邮箱、微信 |
| 住址 | 精确到市/区的地址（如作者单位通讯地址含邮编） |
| 账号 | 学信网/知网/期刊投稿系统的账号线索 |

### 2. 未发表的研究内容 ⚠️ 最容易被忽视

**这一类的风险不比姓名小**：

- **未发表论文的标题**——公开后可能被他人抢题，或在投稿时被认定为"已公开披露"
- **论文正文与章节标题**——期刊查重系统会检索公开网络；**公开自己的稿件可能撞自己的查重**
- **未公开的数据**（裁判文书样本量、访谈材料、案例库编号）
- **尚未定稿的论证思路**——这是最核心的学术资产

> **判断标准**：如果这篇论文**尚未正式发表**，它的题目、章节标题、正文段落
> **都不应出现在公开仓库里**，即使是作为"示例"。

### 3. 第三方信息

- 合作者的姓名与单位（**未经同意不得公开**）
- 访谈对象、调研对象的信息（即使化名，也要评估可识别性）
- 他人未公开的作品、内部资料、审稿意见原文
- 期刊编辑/审稿人的身份线索

## 二、脱敏规则

### 规则 1：示例一律用**虚构/泛化**内容

| 原样（❌ 不可） | 脱敏后（✅ 可用） |
|---|---|
| `张某某*` | `李某某*` |
| `（××大学××学院法学系，××省××市 611731）` | `（××大学××学院，××省××市 000000）` |
| 含真实校名缩写的英文单位行 | `School of ××××, ×× University` |
| 含具体论题的书名号标题 | `《××》"某某"概念探析——以《××》篇…` |
| 具体论文中的正文原句 | `"甲"的对象——"乙"——是既定的规范体系` |
| 具体章节标题 | `（一）X 与 Y：一个文本现象` |

> ⚠️ **连"脱敏前 vs 脱敏后"的对照表本身也会泄漏。**
> 写这类文档时，**"原样"那一列必须也用虚构内容**——
> 否则你等于在示例里把真实信息原封不动地留了一遍。
> （本项目第一版就犯过这个错：在示例里保留了真实的校名缩写。）

**关键**：脱敏后**仍要能说明规则**。示例的作用是让人看懂"改了什么、为什么改"，
不是展示具体论文内容。

### 规则 2：保留**统计量**，不保留**原文**

统计量不具识别性，且正是论据所在：

- ✅ 可以写：「AI 稿有 634 处半角直引号，定稿为 0」
- ✅ 可以写：「129 处差异，68 段 → 64 段」
- ❌ 不可写：「某某论文第 3 章第 2 节原句是……」

### 规则 3：作者署名用**昵称或 GitHub 用户名**

`LICENSE` 与 `CREDITS.md` 的版权声明需要署名，但**不必用真实姓名**：

- ✅ `Copyright (c) 2026 <你的 GitHub 用户名>`
- ✅ 昵称
- ❌ 真实姓名 + 学校 + 学院（三者组合会直接定位到个人）

### 规则 4：不提交真实的论文文件、题录、PDF

`.gitignore` 应排除：

- `CNKI-*.txt`（题录含检索痕迹）
- `*.pdf` / `*.caj`（受版权保护，且可能含个人批注）
- `论文正文_*.md`、`写作启动包_*.md`、`文献精读笔记_*.md` 等个人工作文件
- `*.docx` 生成的成品（除非是脱敏的示例）

## 三、发布前必做：隐私扫描

```bash
# 全仓扫描（默认扫描当前目录）
python scripts/check_pii.py .

# 自定义敏感词（比如把你的姓名、学校写进一个文件）
python scripts/check_pii.py . --terms 我的敏感词.txt

# 只看结论
python scripts/check_pii.py . --quiet
```

脚本会检查：

| 类别 | 检查内容 |
|---|---|
| 身份信息 | 常见姓氏+名字模式、学校/学院名、邮箱、手机号、邮编、身份证号 |
| 联系方式 | 邮箱、手机、QQ/微信痕迹 |
| 本地路径 | 盘符绝对路径（会泄漏机器用户名与目录结构） |
| 未发表内容 | 常见论文标题模式、`【`…`】`占位符残留 |
| 提交卫生 | 是否误提交 `.pdf` / `CNKI-*.txt` / 真实 `.docx` |

> ⚠️ 自动扫描**不能替代人工通读**。脚本只能抓模式化信息，
> 定稿前请自己再读一遍所有待发布的文档。

## 四、⚠️ 一条最容易被忽略的：**Git 历史也会泄漏**

**只修改当前文件是不够的。** 如果你曾经把敏感内容提交过一次，
即使后一次提交删掉了，**它仍然留在 Git 历史里**，别人可以：

```bash
git log -p            # 看到每一次提交的完整内容
git show <commit>     # 看到那次提交的原文
```

### 三种处理方式（按推荐度）

| 方式 | 做法 | 适用 |
|---|---|---|
| **① 先本地清理再首推**（推荐） | 在**第一次推送之前**就完成脱敏，让敏感内容从未进入远端 | 大多数情况 |
| ② 新建仓库 | 删掉旧仓库，把清理后的内容作为首次提交推上去 | 已推送但 star/fork 很少 |
| ③ 重写历史 | `git filter-repo` 或 BFG 清理历史 | 已有很多 star/fork，不想换地址 |

> **最佳策略：把这个技能包当作"每次发布前都要过一遍隐私扫描"的对象。**
> 宁可晚发一天，也不要发了再删——搜索引擎与 fork 会留存副本。

## 五、本技能包已做的脱敏处理（记录）

| 位置 | 处理 |
|---|---|
| `references/15` 全文 | 姓名 → `张某某`；学校/学院/英文单位 → `××大学××学院` / `School of ××××, ×× University` |
| `references/15` 示例 | 论文标题、章节标题、正文原句 → 泛化为 `《××》`「甲/乙/丙」等中性替代 |
| `references/15` 统计量 | **保留**（634 处直引号、129 处差异、句长基线等），因其不具识别性且是论据 |

| `.gitignore` | 已排除 PDF、题录、个人工作文件 |

> 使用本技能包的人，请按本章第四节，在**首次推送前**用 `check_pii.py` 自查一遍。

## 六、给别人用时的提醒

如果你把这套流程用于**帮别人改论文**（同学、合作者），额外注意：

- 未经对方同意，**不要把对方的论文内容放入自己的公开仓库**；
- 脱敏不止改名字，还要处理**可推断出身份的组合信息**
  （如"某校法学院 + 某研究方向 + 某年发表"三者叠加即可定位）；
- 若素材来自**案件材料、访谈记录**，须优先遵守个人信息保护相关法律规定
  与所在机构的伦理要求，**不确定时不要公开**。

**一句话原则**：

> **公开的是"方法"，不是"素材"。**
> 规则可以分享，别人的论文不行，自己未发表的也不行。
