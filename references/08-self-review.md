# 08 · 模拟审稿自审

## 一、为什么投稿前要"自己当一次审稿人"

作者视角和审稿人视角看到的**不是同一篇文章**。

作者看得见自己的论证意图，会自动补全没写出来的逻辑；审稿人只看纸面，缺什么就是缺什么。所以投稿前必须**换视角再读一遍**，而且要以"挑错"而非"确认"为目的。

实战验证：某稿在自审中查出 12 个问题，其中 3 个是"必改硬伤"——地方归属错误、口径混淆、期刊文献全部缺页码。这些问题若流到审稿人手里，会形成"此人治学不严"的负面第一印象，杀伤力远超论证层面的瑕疵。

---

## 二、操作规程：跨窗口 + 跨模型（不可省）

> **这一节是硬性的操作要求，不是偏好。** 审稿环节必须：
> **① 在独立的窗口里做；② 用更强的模型做。**
>
> 真实协作中就是这么做的——这不是巧合，是它有效的原因。

### 为什么必须换窗口

同一个窗口里堆着**写作启动包、文献精读笔记、每一轮的修改理由**。
在这个上下文里读稿，AI 会不自觉地：

- 替自己此前的判断辩护（"我这样写是因为……"）
- 自动补全稿件里**没写出来**的逻辑（因为它记得本来想说什么）
- 把"我知道这里想表达什么"误当成"读者能读懂"

**真实审稿人只看到一份稿件。** 所以隔离才是审稿人视角的前提。

### 为什么必须换更强的模型

起草阶段要的是**产出速度**，审稿要的是**挑错能力**——这两件事对模型的要求不同。
审稿需要：长文交叉比对、发现事实矛盾、识别论证跳步。
**这一步值得投入更贵的模型**，因为它决定了后面所有修订的方向。

### 隔离带来的硬约束：交接只能靠文件

窗口隔离之后，审稿窗口看不到写作窗口的任何东西。
所以**审稿意见必须落盘为文件**，才能带回写作窗口执行。

> 这就是"自审必须落盘"的真正原因——不是留档，是**跨窗口交接的唯一通道**。
> 只把意见变成 `replace()` 语句改掉的（见 `09-revision-discipline.md`），
> 等于把审稿结果销毁了。

### 给审稿窗口什么、不给什么

| 给 | 不给 |
|---|---|
| ✅ **清洗过的稿件**（`审稿稿_M<N>.md`） | ❌ 写作启动包（写着作者的论证意图） |
| ✅ 审稿任务说明（`审稿任务说明_M<N>.md`） | ❌ 文献筛选清单、精读笔记 |
| ✅ 目标期刊的投稿要求（如有） | ❌ 对话记录、修改理由、版本对比 |
| | ❌ 上一轮的审稿意见（第二轮除外） |

**为什么连"修改理由"都不给**：如果审稿人要读到作者的意图说明才能理解某段论证，
那这段论证在稿件里就是失败的——**这正是要指出的问题**。

### 一键生成审稿任务包

```bash
# 第 1 轮
python scripts/mk_review_packet.py 论文正文_XX_v5.md --round 1

# 匿名评审（移除作者信息与基金项目）
python scripts/mk_review_packet.py 论文正文_XX_v5.md --round 1 --anonymize

# 连 [待核] 标记一起清掉（模拟真实审稿人看不到任何内部标记）
python scripts/mk_review_packet.py 论文正文_XX_v5.md --round 1 --strip-todo
```

脚本会做两件事：

1. **清洗稿件** → `审稿稿_M1.md`
   移除只有作者该看到的东西：元信息块（`> 写作状态：全文初稿 v3·编号定稿`）、
   内部文件标题（`# 论文正文_XX（全文 v5）`）、HTML 注释、状态行、占位符，
   并把题目提为规范一级标题。
   > 未清洗的稿件会让"审稿人"看到内部标记，从而污染它的判断。
2. **生成审稿指令** → `审稿任务说明_M1.md`
   写明它的身份（外审专家）、材料边界（哪些不给、为什么不给）、
   必查的四类硬伤、评分维度、输出格式（五要素）、落盘要求。

### 完整操作流程

```
① 在写作窗口执行 mk_review_packet.py，生成审稿任务包
   ↓
② 新建一个独立窗口（不要用写作窗口）
   ↓
③ 选用更强的推理模型
   ↓
④ 把「审稿任务说明_M1.md + 审稿稿_M1.md」交给它
   ↓
⑤ 它落盘产出 审稿意见_M1.md
   ↓
⑥ 回到写作窗口，把 审稿意见_M1.md 交给写作侧 → 执行修订
   ↓
⑦ 修订后生成第 2 轮任务包 --round 2
```

### 第二轮的特别要求

第二轮可以（且应该）把**第一轮的审稿意见**一并给审稿窗口，
并要求它额外核查：

- 上一轮的意见**是否真的落实了**（逐条对照原文）
- 修订是否**引入了新的问题**（改了一个数字，忘了改对应的另一个数字）

> 修订几乎一定会引入新错误，所以第二轮不能省。

## 三、评分维度（建议权重）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 选题价值 | 25% | 是否真问题？是否有现实/理论意义？是否同质化？ |
| 论证质量 | 25% | 逻辑链是否完整？有无"结论先于证据"？有无数值嫁接？ |
| 创新性 | 20% | 有无知识增量？是否只是文献综述的搬运？ |
| 文献质量 | 15% | 是否覆盖重要文献？有无遗漏关键对手？引注是否规范？ |
| 表达规范 | 15% | 结构、术语一致性、格式 |

输出总分与结论（**推荐修改后发表 / 修改后再审 / 不宜采用**）。

## 四、四类必查的"低级但致命"问题

### 类型一：事实性硬伤
地名、机构归属、年份、案例归属、人物职务。

> 实例：把"江西九江、江苏吴江和太仓、山东潍坊"写成"江苏九江、吴江、太仓、潍坊"。
> 这类错误审稿人一眼可见，且**直接损伤全文可信度**。

**检查方法**：把全文所有地名/机构名抽出来，逐个核对上级行政归属。

### 类型二：口径混淆
地方 vs 国家、不同时点、不同统计范围。

> 实例：把四川地方试点缴费标准表述为"国家试点通行标准"。

**检查方法**：每一组数据问三个问题——谁的？什么时候的？统计口径是什么？

### 类型三：引注不达标
缺页码、缺发布日期、缺网址、政策文件未入列表、刊名错误、重号、跳号。

> 实例：期刊文献全部只到"年第 X 期"，缺起止页码；
> 实例：正文引用了某份规范性文件（如《××××指引》，××发〔2023〕50号），却未列入参考文献；
> 实例：刊名写成"《人民论坛·学术前沿》"——这是两本刊物。

**检查方法**：跑 `validate.py`；然后逐条看参考文献是否"五要素齐全"（作者/题名/载体/年/页码或日期）。

### 类型四：数值嫁接
把两个不同基准的巧合数字说成"恰相对应"。

> 实例：把"应然计发比例 60%—80%"与"现状待遇差距 60%—80%"说成"恰相对应"。

**检查方法**：全文搜索"恰/正好/恰好/相对应/相吻合/印证"，逐个复核。

## 五、审稿意见的写作格式

每条意见必须包含五要素，缺一不可：

```markdown
### 问题N【类别·严重度】一句话标题

- **位置**：第X章（二），第NN行
- **原文**："……被引用的原句……"
- **问题**：为什么这是问题（说清道理，不要只说"不好"）
- **修改方案**：给出具体可替换的文字
  > "……建议改为的完整表述……"
- **依据**：为什么这么改（引用文献/文件/规范）
```

**关键**：`修改方案` 必须给出**可直接替换的完整文字**，而不是"建议进一步论证"这类空话。作者拿到意见后应该能直接动手，不需要再想一遍。

## 六、意见分级与执行顺序

按优先级分三级：

| 级别 | 内容 | 执行顺序 |
|---|---|---|
| **必改硬伤** | 事实错误、口径混淆、引注硬伤 | 1（先改） |
| **引注补正** | 补页码、补日期、补入政策文件 | 2 |
| **论证与表达打磨** | 逻辑衔接、概念统一、段落拆分 | 3 |
| **加分项**（可选） | 文献综述加厚、正面回应最尖锐质疑、核心概念前置 | 4 |

## 七、审稿人特别提醒栏

报告末尾应有一节"审稿人特别提醒"，用一句话点出**最致命的 2—3 处**，并说明为什么它们优先级最高。例如：

> 本文整体已达"修改后可投稿"水准，最需警惕的是**第 1 条地方归属错误**与**第 3 条页码缺失**——这两类属"低级但致命"的问题，审稿人常据此对全文严谨性形成负面第一印象，务必优先清除。第 2 条缴费基准额口径、第 7 条数值嫁接，关系到论证的可信度，建议重点打磨。

## 八、给"原作 AI"的执行提示

报告末尾要写一节执行提示，把意见转化为**明确的动作序列**：

```markdown
## 给"原作AI"的执行提示
以上 N 条按优先级排序。建议执行顺序：先改硬伤（1→2→3），再补引注（4→5→6），
后打磨论证（7→12），最后做加分项。涉及"需核实"的条目，**先核验原文再落笔**，
不确定处保留"待核"标记，不要虚构页码或刊名。
```

这一节让自审报告变成**可执行的工单**，而不是一份读后感。

## 九、两轮原则

至少做两轮自审：
- **第一轮**：正文初稿完成后，重点查硬伤与引注；
- **第二轮**：修订稿完成后，重点查"上一轮的意见是否真的落实了"以及新引入的问题。

> 修订常常引入新错误（改了一个数字，忘了改对应的另一个数字）。所以第二轮不能省。
