# 怎么推广、怎么涨 star（以及现实的预期）

> **先说结论，避免期待落空**：
>
> - GitHub star 的数量**几乎完全取决于推广，不取决于仓库本身质量**。
>   一个无人知道的优秀仓库，star 数是 0；一个平庸但被大 V 转发一次的仓库，能有几百 star。
> - 对"中文法学学术写作"这个**极窄**题材，**20—100 star 已经是相当好的结果**。
>   破 500 需要运气或被大号转发，破 1000 基本不可能靠自然增长。
> - **对法学类求职，star 数的权重极低。** 招聘方更在意你有没有通过法考、
>   有没有征文获奖、实习经历。star 是"顺便证明有点影响力"，不是主线。
>
> 下面给的是**能提高概率的具体做法**，不是"保证涨 star"的承诺。

---

## 一、发布前：把"十秒吸引力"做出来

别人点进仓库，**十秒内决定要不要点 star**。这十秒看三样东西：

1. **第一行标题**能不能让他觉得"这说的就是我"
2. **有没有立刻看到效果**（输出截图/代码块）
3. **README 在手机上是否可读**（很多人在手机上看）

### 检查清单

- [ ] README 最上方是**问题**，不是"这是什么"
      —— ❌"一套人机协作论文写作工作流"　✅"法学论文栽跟头，多半栽在编号错位和'本文'出现在摘要里"
- [ ] README 里有一段**真实的运行输出**（本项目已放在 [`examples/演示输出.md`](../examples/演示输出.md)）
- [ ] 仓库 About 栏的 Description 填了，**Topics 标签**填满
- [ ] 首页没有大段晦涩术语，中文为主
- [ ] 有一个 `examples/` 目录，让人不用安装就能看到价值

### 建议填的 Topics（GitHub 右上角 ⚙️ About → Topics）

```
academic-writing  paper-writing  law  legal-research  citation
gbt7714  cnki  学术写作  法学  论文写作  ai-agent  workflow
chinese-nlp  productivity-tools  research-tools
```

> 注意：GitHub 的 Topics 用**英文小写连字符**最有效（中文标签可搜到的概率低），
> 所以两者都加。

### 仓库名与描述

- 仓库名：保持 `scholarrelay`（英文，便于检索和分享链接）
- Description 建议（60 字以内，要出现在搜索结果里）：

  > 法学/中文学术论文写作工作流：引注编号校验、AI 腔检测、版本塌方预警｜10 阶段协议 + 8 个校验脚本

## 二、发布后：发到哪里（这才是关键）

**同一个内容，发在错的地方 = 0 star；发在对的地方 = 几十到几百 star。**

按投入产出比排序：

| 渠道 | 适合 | 效果 | 注意 |
|---|---|---|---|
| **小红书** | 法学生、考研考公人群 | 🟢 高 | 图文形式，标题要"接地气"。**这是法学生密度最高的平台** |
| **知乎**（问题下回答） | 学术人群 | 🟢 高 | 找"法学论文怎么写""论文格式"这类问题，写长回答后带链接 |
| **微信公众号投稿**（学术类） | 学术人群 | 🟢 高 | 给"学术写作""法学研究"类公众号投稿，被采用后引流明显 |
| **B 站 / 抖音** | 泛人群 | 🟡 中 | 做 60 秒演示视频：贴一段错乱编号 → 跑脚本 → 一秒标红 |
| **法学学术微信群 / QQ 群** | 精准人群 | 🟡 中 | 转化率高但天花板低，十几个群也就几十 star |
| **即刻 / V2EX / 少数派** | 技术人群 | 🟡 中 | 技术圈对"AI + 垂直场景"有兴趣，但法学人少 |
| **GitHub 自身**（Topics 搜索） | 被动流量 | 🔴 低 | 长期有点用，短期几乎没有 |

### 内容怎么写（三个渠道的示例）

**小红书**（图 2—4 张，第一张是"错误 vs 检测"对比截图）

> 标题：**法学论文被导师退回 3 次，我才发现是参考文献编号错位**
>
> 正文：
> 写论文时最容易栽的不是论证，是这些低级错误👇
> ① 同一篇文献重复占了两个编号
> ② 删了几篇文献后，正文编号整段错位
> ③ 期刊文献忘了标起止页码
> ④ 摘要里写了"本文"，法学核心期刊是禁的
> 我把这些做成了能一键检查的脚本，开源免费，链接放评论区～
> #法学 #论文写作 #法学论文 #毕业论文 #法学生

**知乎**（在"法学论文写作"类问题下写回答）

> 开头直接给结论和痛点，中间讲**为什么这些规范存在**（体现专业度），
> 结尾放链接。**不要在开头就放链接**，会被踩。
> 重点是让人看出你懂行，而不是来打广告。

**技术社区**（V2EX / 即刻）

> 标题：**我把"和 AI 一起写论文"踩过的坑做成了一个工具集**
>
> 说清两件事：① 为什么选这个垂直场景（AI 在知网下载不了全文，这个不对称决定了分工）；
> ② 最有意思的发现（版本字数曲线能预警结构塌方）。
> 技术圈吃"具体发现"，不吃"我做了一个 XX 系统"。

## 三、时间与节奏

- **发布时机**：工作日上午 9—11 点，或晚上 20—22 点（通勤和睡前刷手机的高峰）
- **节奏**：不要一次全发。**先发 1 个平台，看反应，再调整文案发第二个**。
  同一个文案原封不动发五个平台，效果会一次比一次差。
- **回应评论**：前 2 小时的评论回复率直接影响推荐量。这是最划算的投入。
- **后续更新**：每次推送新版本时，在社交平台同步一句"新增了 XX 检查"——
  老读者会回访，也可能带来新的 star。

## 四、明确不要做的

| ❌ 不要 | 原因 |
|---|---|
| 买 star / 用互 star 群 | GitHub 会清理，且 star 数异常会被识别；对求职是**减分**（面试官一问就穿） |
| 在别人仓库或 Issue 里留"求 star" | 会被拉黑，损害长期声誉 |
| 把"求 star"当主要内容 | 转化率极低，且显得项目没有内在价值 |
| 夸大功能（"已帮助上千人"） | 简历/面试会追问，一查就穿 |
| 用"AI 自动写论文，一键生成"做卖点 | 触碰学术诚信红线，会招来大量负面评论 |

> ⚠️ 最后一条尤其重要。**这个项目的立场是"用工具守住规范"，不是"用 AI 代写"。**
> 宣传时必须说清这个区别，否则会被误认为是代写工具——那对法学专业形象是**负资产**。

## 五、如果目标真的是求职，怎么分配精力

把 star 数当成副产品，把下面这些当主线：

| 优先级 | 事项 | 说明 |
|---|---|---|
| 1 | **法考通过** | 法学求职的硬门槛 |
| 2 | **征文获奖 / 论文发表** | 学术能力最硬的凭证 |
| 3 | **实习经历** | 实务能力凭证 |
| 4 | **这个开源项目** | 证明"规范意识 + 方法论能力"，是**差异化亮点** |
| 5 | star 数 | 几乎不重要，有最好 |

**换句话说**：把项目认真写好、能自圆其说地讲出来，比盯着 star 数有意义得多。
那 20 个 star 里如果有一个是目标单位的 HR，就已经达到目的了。

## 六、发布日操作清单

发布当天照这个顺序做一遍：

- [ ] 仓库 Description 填好，Topics 填满（中英各半）
- [ ] README 在手机上打开检查一遍排版
- [ ] `examples/演示输出.md` 能正常打开
- [ ] `LICENSE` 和 `CREDITS.md` 里的作者名已改成自己的
- [ ] 打一个 Release（`v1.0.0`），让仓库显得"有版本管理"
- [ ] 准备 3 张截图：① 编号校验报错 ② 版本曲线塌方预警 ③ 摘要"本文"告警
- [ ] 选一个平台首发，写好文案
- [ ] 发布后 2 小时内守在评论里回复
